# 司令塔を Claude デスクトップの Code タブにする

設定: `LANES_COMMANDER="${LANES_COMMANDER:-claude}"`

司令塔（レーンを起動し、終わったら次工程へつなぐ役）を、Mac の Claude デスクトップアプリの Code タブのセッションに任せる形です。
外の Bot を用意しなくてよく、Mac 1 台で完結します。

`LANES_COMMANDER=claude` のときの意味:
（この設定は運用の印です。キットの動きとして変わるのは、`lanes-doctor.sh` の「司令塔」の表示（監視の回し方の案内）と、`LANES_COMMANDER=claude` で `lanes-watch.sh` を `--until-wake` なしで起動したときの注意の 1 行だけで、ランチャや判定の動きは変わりません）
- 監視の `WAKE:` を受けて動くのは、Code タブのセッション自身。
- そのセッションが司令塔なので、セッションの中で小さな作業を自分で直すのではなく、作業はレーンに出して自分はつなぐ役に徹する。

## できること・できないこと（先に知っておいてほしいこと）

- **Mac とセッションが起きている間だけ動きます。** Mac のスリープ・アプリの終了・セッションを閉じると監視も次工程も止まります。
  寝ている間も回したいなら、電源につないでスリープしない設定にし、アプリとセッションを開いたままにします。それが難しいなら [commander-grok.md](commander-grok.md) の形が向いています。
- **使用量が増えます。** 監視で起きるたびに司令塔のセッションが考えて動くので、その分 Claude の利用枠を使います。レーン自体の使用量とは別にかかります。

## 仕組み

| 間隔 | セッションがやること | 目的 |
|---|---|---|
| 常時（5 分ごとに見回り） | `zsh <kit>/lanes/lanes-watch.sh --until-wake` をバックグラウンドで実行 | 変化があると `WAKE: <理由>` を出して終了する。終了の通知でセッションが起き、次工程を判断してから、もう一度同じ監視を起動する |
| 10 分ごと（定期実行。`LANES_CHECK_INTERVAL_MIN`） | `zsh <kit>/lanes/lanes-watch.sh --check` | 監視が生きているか（`WATCH OK` / `STALE` / `DEAD`）。exit 1 なら監視を起動し直す。あわせて並列で足せる作業を判断する |

- `--until-wake` は `QUIET`（変化なし）の間は黙って回り続け、`WAKE:` のときだけ終わります。既定は 300 秒間隔・最長 12 時間（`--interval` / `--max-hours`）。
  二重起動は exit 2 で拒否するので、「念のためもう 1 本」は不要です。
- 10 分ごとの定期実行は、Claude Code のループ機能（`/loop 10m ...` のような定期実行の仕組み）などで設定します（間隔を変えるなら `LANES_CHECK_INTERVAL_MIN` も同じ値に）。
  中身は「`lanes-watch.sh --check` を回し、STALE/DEAD なら監視を起動し直し、次工程待ちのレーンと、担当ファイルが重ならない追加の作業があれば起動する」。
- **スクリプトは作業レーンを自分では起動しません。** 起動するのはセッション（司令塔）です。

### 見張りのかけ直し忘れを仕組みで止める（Stop フック）

`--until-wake` は `WAKE:` で終わるので、終わるたびに司令塔がかけ直す必要があります（出力の最後に `RE-ARM:` 行が出ます）。
これを AI の注意だけに頼らないよう、Claude Code の **Stop フック**（Claude が返事を終えようとしたときに必ず走る仕組み）を用意しています。

- 中身: `lanes/hooks/claude-stop-watch-guard.sh`。そのセッションのやりとりの記録に `lanes-watch.sh --until-wake` が出てくる（＝司令塔として見張りを使っている）セッションで、
  `lanes-watch.sh --check` が `WATCH OK` でなく、動いているレーンか次工程待ちのレーンがあるときだけ、返事を終わらせずに「見張りをかけ直せ」と Claude に返します。
  見張りを使っていないほかのセッションには何もしません。止めた後の 2 回目は止めません（抜けられなくなるのを防ぐ）。フック自体が失敗したときも止めません。
- 登録: `~/.claude/settings.json`（全部のセッション）か、司令塔で使うリポジトリの `.claude/settings.json` の `"hooks"` に足します。既にある `Stop` のフックは残して並べます。
  ```json
  "Stop": [{ "hooks": [{ "type": "command", "command": "zsh -f <kit>/lanes/hooks/claude-stop-watch-guard.sh", "timeout": 30 }] }]
  ```
  `install.sh` はこの設定を書き換えません（利用者の設定ファイルなので、自分で足してください）。
- これで防げるのは「見張りを付けないまま返事を終える」ことです。セッションそのものが閉じた・Mac が眠った、は防げません（司令塔が Claude のときの前提どおり）。

### 起動のしかた

Code タブのセッションからは、Bash ツールのバックグラウンド実行でランチャや監視を起動します（セッションが親として残るので、終了の通知も受け取れます）。
短い Shell の中で `nohup ... &` して親を終わらせる形は、環境によって子が止まるので避けます。

## 司令塔がやること

1. **ゴールを衝突しない小レーンに分ける**: 触るファイルが重ならない単位に分け、依存のあるものだけ待つ。
2. **最大並列**: 依存の無いレーンは全部同時に起動する。手順書・テスト用の設定など、並行できる作業も出てきたそばから足す。
3. **起動 60 秒以内に status**: `lanes-status.sh <worktree> <label> --tail 20`。`RUNNING` か `DONE` 以外は起動失敗として末尾付きで報告する。
   **status を見る前に「起動した」と言わない**（言うなら「起動確認 OK: pid / ログのパス」）。
4. **DONE で即次工程**: `WAKE:` で起きたら、実装 DONE → レビュー、レビュー CLEAN → 最終確認 → PR、PR マージ → 後片付け → 次のレーン。待たずにつなぐ。
   つないだら `lanes-watch.sh --until-wake` を起動し直すのを忘れない。
5. **FAILED / DEAD / STALLED は聞かれる前に報告**: 状態 / 経過時間 / 最終出力の時刻 / 次にやること、の 4 点を毎回同じ形で。
   同じ起動を黙って繰り返さない。止めるときは `kill <ランチャの pid>`（`kill -9` はしない）。
6. **CI は見張らない**: PR を作ったら `gh pr merge <PR> --auto --merge --delete-branch` で GitHub の auto-merge に任せ、次に起きたついでに
   `gh pr view <PR> --json state,mergedAt` を見る。マージ済みなら `cleanup-after-merge.sh <worktree> --apply`。
   CI 待ちだけのレーンは作らない。必須チェック（ブランチ保護）が無いリポジトリでは `--auto` が即マージになるので、
   `gh pr checks <PR> --watch --fail-fast` を 1 回待ってから手でマージする。
7. **本番は人の GO**: main への取り込み・本番デプロイ・本番 DB・課金の本番切り替えは、人の明示の GO を待つ。

## 司令塔にしないセッション

`LANES_COMMANDER=claude` でも、すべての Claude のセッションが司令塔になるわけではありません。
人が「このセッションで司令塔を」と決めたセッションだけが上の手順で回し、ほかのセッションは普段どおり小さな作業を自分で直してかまいません。
同じ `$LANES_RUNS_ROOT` に監視を 2 つ立てようとしても、2 つ目は exit 2 で拒否されます。
