# 開発チーム依頼ブリーフ（dev-team-brief）

**このスキルは、司令塔（`LANES_COMMANDER`）が Grok Bot などの外の Bot で、設計担当（デザイナー・フロント・バック）を別に持つ体制向けである。**

新規機能や改善の設計を開発チームの各担当へ振るときのテンプレートを定める。既存のバグ修正には使わない。

## いつ使うか

- ユーザーから新規ゴールが来た直後
- 司令塔が案件を分解して並列に設計依頼するとき
- 設計が曖昧なまま実装に入ろうとしているとき（立ち止まってブリーフ（設計依頼の要件まとめ）を書く）

## 必須フィールド（欠けたら送らない）

```markdown
## 案件
- プロダクト:
- 一言ゴール:（ユーザーが何をできるようになるか）
- 優先: 高 / 中 / 低
- 期限:（あれば）

## スコープ（対象範囲）
- 含む:
- 含まない:
- 既存で触ってよい面:
- 既存で触ってはいけない面:

## 完了条件（Done）
- [ ] 成果物1（例: 画面ステート（状態）一覧 / API（システム間でデータをやり取りする窓口）契約 / 画面遷移図）
- [ ] 成果物2
- [ ] 実装レーン（Claude / Gemini）の指示にそのまま貼れる粒度になっている

## ロール別の依頼
### デザイナー
- 自己完結の範囲:
- 先に出すもの（手前に動く案）:
- やってはいけないこと:

### フロントエンド（画面・ブラウザ側の担当）
- 自己完結の範囲:
- 出すもの（実装可能な差分仕様・状態・フォーム）:
- やってはいけないこと: Mac CLI（コマンドラインで動くツール）の起動・本線コードの編集

### バックエンド（サーバー・データベース側の担当）
- 自己完結の範囲:
- 出すもの（スキーマ（データの構造定義）・エンドポイント（通信の接続先）・データ移行・セキュリティ）:
- やってはいけないこと: Mac CLI の起動・本線コードの編集

## 禁止・制約
- 秘密値をチャットや出力に出さない
- 本番 / `main` ブランチへの直接反映を提案しない（本番反映はユーザーの GO（実行許可）を待つ）
- 実装コードを自分で書かない（設計までを担当し、実装は Mac の実装レーンで行う）
```

## 出し方

1. 司令塔が上の必須フィールドをすべて埋める（空欄のまま送らない）。
2. 開発チームの共有場所へ投稿、または必要なロール（役割）だけに個別送付する。
3. 各担当の設計成果物が揃ったら、司令塔が課題管理ツールの票を作り、共通ランチャ（`<kit>/lanes/run-impl.sh`）で実装レーン（Claude / Gemini。振り分け基準は [lanes](../lanes/SKILL.md) に従う）を起動する。明示的な例外がない限り、設計待ちの間に実装を先行しない。

## 受け取った側の動き

- 自分の「自己完結の範囲」まで完走して返す。
- 不明点は仮定を 1 つ置いて進み、置いた仮定を成果物に明示する。
- 終わったら司令塔に「Done + 成果物」だけを返す。次の実装レーン起動は司令塔が行う。
